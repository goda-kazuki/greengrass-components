結論

手元の Raspberry Pi にある Greengrass デバイスへ、自作コンポーネントを継続的に届けるための開発の土台を作ります。

第一弾は、SCD40 センサーの値(CO2・温度・湿度)を AWS IoT Core へ定期送信するコンポーネントです。複数コンポーネントを扱えるモノレポとし、ビルドとデプロイはスクリプトで自動化します。

AWS 側のリソース作成と CI は今回の対象外です。

要点

  • 届ける仕組みを先に作る。Greengrass デバイスに自作コンポーネントをデプロイし続けられるよう、開発、ビルド、デプロイの土台を整える。
  • まず1つ、センサーの値を送る。SCD40 の CO2・温度・湿度を、定期的に AWS IoT Core へ届ける。
  • 増やしやすくする。複数コンポーネントを1つのリポジトリで扱う。追加はディレクトリを足すだけで済む。
  • デバイスは軽く保つ。uv は開発機だけで使い、デバイス側は Greengrass が前提とする Python と pip だけで動かす。
  • 失敗には単純に対処する。読み取りや送信が失敗したらログを残して続行する。送信できなかったデータは捨て、キューは持たない。
  • 手作業を減らす。ビルドとデプロイはスクリプト化する。テストはハードウェアなしの開発機でも動くようにする。
  • 範囲を絞る。AWS リソースの作成と CI は今回やらない。

判断・対応が必要な点

利用者が事前に用意するもの。このリポジトリは AWS リソースを作りません。
  • 成果物を置く S3 バケット、対象の IoT Thing と Thing Group を用意する。
  • コンポーネントが IoT Core へ送信するために必要な IAM ポリシーと認可設定を用意する。
  • デプロイ時に環境変数 GG_ARTIFACT_BUCKET と AWS_PROFILE を設定する。AWS CLI のプロファイルは設定済みであること。

今後の検討事項として、元文書は次の3点を挙げています。いずれも今回は対応しません。

  • CI(lint とテストの自動化)。必要になった時点で検討する。
  • AWS リソースの IaC 化。複数コンポーネントや複数デバイスを管理する規模になった時点で検討する。
  • 送信失敗時のバッファリングなど、キューイングとリトライの高度化。

背景とスコープ

すでに Raspberry Pi に Greengrass をセットアップ済みです。このリポジトリの役割は、コンポーネントの開発、ビルド、デプロイを管理することです。言語は Python、パッケージ管理は uv を使います。

今回やる今回やらない
  • モノレポ構成の整備
  • センサー値を送信するコンポーネントの実装
  • ビルドとデプロイのスクリプト整備
  • 開発とデプロイ手順のドキュメント整備
  • AWS リソースの作成
  • CI の導入(ローカル実行のみで十分とする)
リポジトリと依存関係の方針

ルートに uv のワークスペースを置き、各コンポーネントは components/ 配下に独立したディレクトリとして持ちます。ビルドとデプロイ用のスクリプトと、デプロイ手順のドキュメントも同じリポジトリに置きます。

uv は依存関係の解決、ロックファイル、テスト実行に使いますが、デバイスには入れません。デバイス側の依存を最小にし、デプロイ時に uv のインストールやネットワーク到達性へ依存させないためです。

ビルド時にロック済みの依存関係を requirements.txt に書き出し、デバイスでは通常の pip3 で導入します。

コンポーネントの設計(scd40-publisher)
センサー接続I2C 接続の SCD40 を、Adafruit のライブラリで読み取る。ユーザー提供の動作確認スクリプトがベース。
実行の流れ起動時にセンサーを初期化し、定期ループで測定して、Greengrass IPC 経由で AWS IoT Core へパブリッシュする。
測定間隔既定は60秒。環境変数またはレシピのパラメータで変更できる。
送信内容CO2、温度、湿度、時刻を JSON で送る。トピックは greengrass-components/scd40-publisher/<thingName>/telemetry。
設定トピック名と測定間隔は、デプロイ時に上書きできるようレシピでパラメータ化する。

エラー時の動作

状況動作
センサー読み取り失敗ログに記録して継続し、次の測定サイクルで再試行する。
IoT Core への送信失敗ログに記録し、そのデータは捨てる。シンプルさを優先し、ローカルキューは持たない。
起動時に I2C デバイスが見つからないエラーログを出して終了する。再起動は Greengrass に任せる。

テスト方針

pytest と mock で、I2C と Greengrass IPC を差し替えた単体テストを用意します。センサー側と送信側は、差し替えやすい構造にします。Raspberry Pi 以外の開発機でも、ハードウェアなしで uv run pytest が動くことを確認します。

ビルドとデプロイのスクリプト
スクリプトやること
ビルドコンポーネント名を指定して実行する。依存関係を書き出し、ソースとレシピとまとめた zip を作る。バージョンは pyproject.toml から取る。
デプロイコンポーネント名とバージョンを指定して実行する。zip を S3 へ上げ、レシピに S3 の場所とバージョンを入れて登録し、対象の Thing または Thing Group へのデプロイを作る。

AWS の認証情報は、環境変数 AWS_PROFILE で指定したプロファイルを使います。前提となる AWS リソースと実行手順は、別途ドキュメント(docs/deploy.md)にまとめます。
